## 存什么

`MvpSession.snapshot()` 返回脱离运行对象的 JSON 数据，`restore(unknown)` 先校验再构造会话。包括：

- 种子、变异概率、召唤/变异 PRNG 状态；地图由同内容版本与种子重建。
- 阶段、当前节点、访问路径、树心、灵露、口袋、本局移出名单、开放树桩。
- 宠物 ID/物种/星级/去重变异列表/总投入、冷却、readyTick、攻击计数。
- 全部敌人、伤害/再生时间、弹道快照、攻击标记和藤蔓剩余时间。
- 模拟 tick、出怪游标、计数器、下一个实体 ID、击杀/漏怪数。
- 待选变异的目标、固定一/两张候选、追加或替换层索引、返回阶段与后台暂停要求；调试标记与当前概率。

UI 的手指、拖动预览、资料浮层、地图视角不保存。`restore` 本身不推进时间；界面继续时强制先暂停战斗/保留变异选择，玩家确认后再推进。恢复后不重新发初始灵露、不再次领奖。

档案 `PlayerProfile` 保存九项引导已读与倍速设置，和本局同一信封提交。新远征重置本局，保留档案；只有继续同一局才保留已经购买或移出的种类。

## 如何落盘

适配 `sys.localStorage`，只操作两个专用键：

- `cute-mutation.archive.v1`：主档。
- `cute-mutation.archive.v1.backup`：上一份成功记录。

信封带 `schema=1`、`content`（见 RunArchive.CONTENT_VERSION）、递增 revision、JSON body 和 FNV 校验和。校验和用于发现损坏，不是防作弊或加密。修改数值、地图生成或战斗语义时须提高内容版本；未来迁移要显式实现，不能用新配置悄悄解释旧战斗。

写入顺序是保存上一份有效记录为备份，再通过单个 setItem 替换主档。成功操作/UI 提交、击杀/漏怪、每模拟秒和后台/pagehide 触发；相同内容不重复写。关闭事件只是兜底，不是唯一保存点。突然终止通常最多回退一个模拟秒，操作与奖励有更及时的检查点。

主档有效则继续；损坏/缺失则尝试备份并明确提示。主档版本不兼容时不自动降级，不静默覆盖。主备都坏则禁用继续，用户确认新远征后才覆盖；不清理其他应用的 localStorage。备份可能比主档少一次操作，恢复会提示这一限制。

保存失败立即暂停并盖住操作，允许重试；用户可明确选择“本次不保存，继续试玩”。该模式在菜单和首页提示，关闭后不会假称能恢复，已有有效旧档也不会被主动删除。

## 首次指引

选路、召唤、布阵、合成、变异、铲子、绳索、营地、驿站，共九项。按当前场景触发；弹窗冻结模拟并阻止点击穿透，可逐项确认或一次跳过。已读后不占常驻 HUD，菜单可重新显示。

变异引导不代替正式双卡选择；查看引导、检查资料或重建 UI 不抽随机、不花灵露。恢复时不会重新抽候选。教学允许正常随机结果，不强制首两只同种、不暗改变异概率。

## 自动化验收

- 连续战斗与恢复后逐 tick 的状态、冷却、弹道和未来随机结果一致。
- 待选变异反复读取保持同一目标/双卡/随机流。
- 既有藤蔓、口袋移出与节点奖励不丢失、不重复发放。
- 完整随机远征在每个节点恢复，与不中断运行的统计一致，包含完成状态。
- 损坏、校验失败、未来版本、配额错误和失败后重试有明确结果，保留有效旧档。
- 引导已读与倍速随档案保留；新远征仍只带猫/兔。

执行 `npm test`、`npm run typecheck`、`npm run typecheck:tests`。随机循环使用 `npm run balance`，报告写入 `.mvp/random-balance.json` 与 `.mvp/random-balance-no-mutation.json`。统计是固定策略模拟，不是真实玩家通关率。真机存储行为、系统强杀、多指和安全区仍需要硬件验收；当前没有账号或云存档。
