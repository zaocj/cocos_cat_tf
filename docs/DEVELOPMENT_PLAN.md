### 仅竖屏要求（覆盖早期横屏假设）

- 编辑器设计宽高为 720×1280，由编辑器 Project Settings 修改；Web Mobile 通过结构化构建配置明确 orientation=portrait。
- 高于 16:9 的竖屏固定宽度，额外高度给战场；较短竖屏使用 SHOW_ALL 留边。横向和正方形窗口不开放玩法，显示竖屏提示。
- `PortraitLayout` 以统一缩放转换竖向逻辑路径、敌人、弹道、树桩与射程；投影不改变战斗距离、速度、伤害或收支。
- 触点通过 UITransform 转为布局局部坐标，再在 88 单位触摸区域内按距离选择最近树桩，避免小屏相邻区域被后创建节点抢占。
- 顶部 HUD，中间纵向战场，底部四个纯头像与控制按钮，HUD 下为宠物数据卡；后备改为遮挡输入的伙伴选择弹窗。
- 转横屏时冻结战斗、灵露和输入，恢复竖屏只自动恢复原本运行的战斗，不解除玩家手动暂停；退出到后台不自动恢复。
- 23 项测试通过，包含 20 项规则与 3 项竖屏几何/触点验证；实际旋转、召唤和后备交互验收见 MVP_ACCEPTANCE。

用户于 2026-11-05 指定先验证四项：游戏可运行；近战/远程两种宠物可放置；敌人进入基地扣血并立刻结束；开局通过分岔路线进入战斗。随后确认加入灵露与战斗中放置。本节优先于后续完整版本范围。

### 灵露版实现规则

- 每战斗节点灵露重置 60；在准备和战斗阶段，选择猫/兔/鹿/菇并点击空树桩花 30 灵露召唤，同种可多只。
- 仅战斗运行时每模拟秒 +2 灵露，击杀每只 +2；暂停、地图、准备与结算不产出。领域层按固定 tick 发放，被击杀敌人移除后不会重复奖励。
- 最多部署 6 只，后备计入持有上限 12；每只独立实例 ID 与物种 ID 分离。下个节点保留小队与位置，只重置战斗计时和灵露。
- 首次召唤收费；已有宠物移动、交换、收回、重新部署免费，不返还灵露。战斗搬迁设置 readyTick，停手 30 tick（1 秒），不重置攻击冷却。
- 余额不足、满员、非法树桩、已占位置、暂停和错误阶段均在领域层拒绝，失败不扣费；暂停标记进入领域层，直接调用命令也不能绕过。
- UI 区分召唤物种与选中实例：点卡片进入召唤，点场上/后备宠物进入免费搬迁，显示灵露余额、价格、缺额、部署数和后备按钮。
- 本轮只扩展灵露、实时召唤和跨关保留；合成、变异与捕捉解锁作为后续阶段，未纳入本次完成项。

### 拖动召唤实现

- 召唤卡注册 TOUCH_START/MOVE/END/CANCEL，按触点 ID 跟踪；移动超过 12 设计单位进入拖动，原卡片节点在手势结束前保持存活。
- 触点转换为 UI 局部坐标，复用 portraitSlotAt 选择树桩；预览显示头像、空位高亮和射程，松手直接调用 summonPet，只提交一次。占用位置不能变成搬迁/交换。
- Cocos 3.8.8 将卡片外松手改发节点 CANCEL，用核实的原始事件码区分正常松手和真实取消。后台、转屏、UI 重建、禁用清理手势，暂停不能拖放；点击选择仍保留。
- 删除调整位置后的灵露提示，原有搬迁规则保持不变。

## 3. 技术架构与目录

### 3.1 分层与依赖方向

```text
JSON 配置 → ConfigRepository → 纯 TypeScript 规则与状态
                                   ↑
                           应用命令与流程编排
                              ↑          ↓
                         Cocos 输入    领域事件 / 只读快照
                                            ↓
                              Cocos 场景、UI、动画和音效

平台存储 / 资源加载 / 日志 → 通过接口接入应用层
```

- **domain：** 不导入 `cc`，不保存 `Node`、`Vec3`、Tween、资源对象；负责规则、战斗模拟和随机状态。
- **application：** 处理玩家命令、流程切换、跨模块事务和保存。所有资源与队伍变动从这里进入。
- **presentation：** Cocos 组件负责点击、拖动、展示和特效；不得在动画回调里发放奖励、扣树心或判定命中。
- **infrastructure：** 负责 JsonAsset 加载、本地存储、事件日志和资源缓存。
- 暂不引入 ECS、复杂依赖注入框架、服务器或通用脚本语言。使用明确的类、接口与组合即可。

### 3.2 计划目录

```text
assets/
  scenes/Boot.scene
  scripts/
    domain/
      model/             # RunState、PetInstance、BattleState 等
      battle/            # BattleSimulator、Path、Targeting、Damage、Status
      pets/              # PetStats、MergeService、MutationService
      route/             # RouteGenerator、RouteValidator
      economy/           # RewardRules、NodeRules、RelicEffects
      random/            # SeededRng、随机流派生
    application/         # GameSession、CommandHandler、流程与事务
    infrastructure/      # ConfigRepository、SaveRepository、日志适配
    presentation/
      bootstrap/         # GameBootstrap、SimulationDriver
      battle/            # BattlePresenter、PetView、EnemyView、ProjectileView
      map/               # RouteMapPresenter
      ui/                # 队伍、奖励、合成、变异、结算等面板
  prefabs/
    battle/              # 宠物、敌人、弹道、树桩、树心表现
    ui/                  # 卡片、节点、弹窗
  resources/config/      # 按路径动态加载的 JSON 配置
  art/                   # 静态引用的贴图与字体
  audio/                 # 静态引用的音效与音乐
tests/                   # 不依赖引擎的规则与模拟测试
tools/                   # 配置、路线、资源引用和回归检查
docs/
  GAME_DESIGN.md
  DEVELOPMENT_PLAN.md
```

上面的文件名表示职责边界，实施中可合并很小的模块，避免制造大量空类。`assets/` 下新增目录、脚本和资源均交由编辑器生成 `.meta`。

### 3.3 场景组织

首版使用单入口 `Boot.scene`，其下挂载 `GameBootstrap`，启动后切换界面根节点，减少跨场景对象和资源释放问题。单场景方案也必须在退出战斗时完整清理战斗实例。

```text
Boot
  Canvas
    SafeAreaRoot
      ScreenRoot          # 入口 / 地图 / 战斗 / 结算
      ModalRoot           # 合成 / 变异 / 奖励 / 暂停
      ToastRoot
    DragRoot              # 拖动预览，不持有正式队伍状态
  GameBootstrap
```

启动顺序：加载并校验配置 → 读取档案与存档 → 创建会话服务 → 订阅界面事件 → 打开入口或恢复界面。首版原型可由挂载组件运行时创建占位节点；正式可视层再替换为编辑器制作的预制体，保留同一命令接口。

## 4. 数据模型、配置与状态机

### 4.1 核心数据

| 数据 | 关键字段 | 约束 |
| --- | --- | --- |
| `PetDefinition` | 物种 ID、基础攻击/攻速/射程、能力 ID、适用词条 | 只读配置；羊的各星级助威使用独立表 |
| `PetInstance` | 实例 ID、物种 ID、1～3 星、可空变异 ID | 只保存基础身份，最终属性通过纯函数计算 |
| `RunState` | 远征 ID、内容版本、种子、阶段、树心、金币、催化露、队伍、遗物、保底、路线、当前节点、待结算事务、统计 | 本局唯一可信来源，禁止 UI 另存一份金币或队伍 |
| `RouteGraph` | 区域、节点 ID、层号、类型、连线、地图/遭遇/奇遇 ID、威胁标签 | 无跨层边、无死路；访问和完成分别记录 |
| `Deployment` | 树桩 ID → 宠物实例 ID、索敌模式 | 一宠一桩、最多 6 只；不把上一地图树桩 ID 带入新地图 |
| `EnemyState` | 实例 ID、类型、路径 ID、路径距离、生命、状态、出生序号、首领阶段 | 路径距离决定位置，不用节点坐标反推逻辑位置 |
| `ProjectileState` | ID、来源宠物 ID、目标 ID、位置、速度、发射时伤害参数、命中效果 | 锁定目标；目标失效则销毁，不重新索敌 |
| `BattleState` | 战斗 ID、阶段、tick、波号、出怪游标、敌人、弹道、攻击计时、计次能力、临时状态、遗物使用标记、部署、运行统计 | 可序列化，恢复不重新开波 |
| `PendingMerge` | 操作 ID、素材 ID、结果实例、候选词条、默认词条、概率、已消费催化露、状态 | 恢复时继续同一选择，不重新消耗或抽取 |
| `RewardTransaction` | 事务 ID、节点 ID、固定收益、候选、选择结果、领取游标、已处理奖励项、完成状态 | 支持逐只领取与幂等结算 |
| `ProfileState` | 首次教学进度、图鉴、远征记录、设置 | 与本局存档分离，但用同一保存信封提交相关变动 |

ID 使用远征内递增计数器，计数器存档；物种 ID、词条 ID 等配置键使用稳定英文标识，显示中文名称由配置提供。不要用 `node.uuid`、数组下标或 `Date.now()` 充当玩法对象 ID。

| `battle-maps.json` | 世界单位路径点、树桩、入口、终点与表现映射 |
| `encounters.json` | 固定遭遇 ID、地图 ID、各波出生时刻/入口/类型/数量/生命倍率 |

| `relics.json` | 6 件遗物参数、触发时点与适用条件 |
| `events.json` | 4 奇遇的文案、前置、代价与收益；效果来自有限枚举处理器 |

配置通过 `resources.load` 加载 `JsonAsset`，路径相对于 `resources/` 且不带 `.json`。加载后立即校验：重复 ID、缺失引用、负数、非有限值、无效范围、路径零长度、波次排序、词条池不足等。错误阻止进入远征并输出定位，不用静默默认值掩盖问题。资源路径与加载方式遵循 [Cocos 动态资源加载文档](https://docs.cocos.com/creator/3.8/manual/en/asset/dynamic-load-resources.html)。

内容配置具备 `contentVersion`。远征记录创建时的版本，调数值后不把旧局当作同版本继续；提供明确的不兼容提示，保留图鉴与记录。开发期需要迁移时写显式迁移器，不静默重置存档。

### 4.3 流程状态机

```text
入口 → 地图 → 节点处理中 ─→ 战斗准备 → 波次运行 → 波间准备 ─┐
                 │                           ↑             │
                 │                           └─────────────┘
                 │                                  ↓ 最后一波
                 └→ 非战斗节点 → 奖励结算 → 节点完成 → 地图 / 下一区域
                                                     ↓
                                              通关 / 树心归零失败
```

合成选择属于允许整理队伍阶段内的阻塞子状态，暂停属于战斗阶段上的独立标记。不要把暂停错误映射成波间准备，也不要仅用“弹窗是否可见”判断能否操作。

命令统一返回成功结果或明确原因码，例如 `WRONG_PHASE`、`ROSTER_FULL`、`NOT_CONNECTED`、`INSUFFICIENT_GOLD`、`ALREADY_RESOLVED`。界面按钮禁用只是提示，领域层仍要检查，防止连点和旧回调绕过规则。

## 5. 塔防战斗的具体实现

### 5.1 时间、路径与显示

1. `SimulationDriver.update(realDt)` 驱动纯逻辑模拟，固定步长暂定 **1/30 秒**，使用累加器处理渲染帧率差异。
2. 倍速只影响进入累加器的模拟时间；所有出怪、攻击、减速、光环与首领计时都读取模拟时钟。暂停时不增加模拟时间，UI 仍可操作。
3. 每帧最多推进有限步数，超量时间留待后续帧处理；切后台时暂停并保存，恢复时清除墙钟间隔，不把数分钟后台时间补算成战斗。
4. 道路是世界单位折线，预计算每段长度和累计长度；敌人记录已走距离，根据距离插值出位置。一次步进可能跨多段，需要循环消耗距离。
5. 双入口分别保存路径，统一比较到共同终点的剩余路程；所有路径最终抵达同一树心。
6. 逻辑坐标转换为 `BattleRoot` 的局部坐标；原型取 1 格 = 80 个设计像素，画面缩放不改变逻辑射程和速度。
7. 表现节点只跟随快照插值。不能用 Tween 完成回调驱动敌人到终点、弹道命中或波次结束。

### 5.2 固定步内的处理顺序

同种子与同命令序列必须按同一顺序运行：

1. 处理本 tick 到期的出怪事件，分配稳定出生序号。
2. 到期状态失效，推进首领阶段计时；将所有敌人位置推进至本 tick 末并标记待离场对象。
3. 按推进后位置刷新光环、羊的助威与减速覆盖快照。
4. 依据冷却和索敌顺序发起攻击，记录计次能力，创建逻辑弹道。
5. 推进弹道，以弹道 ID 顺序结算命中与范围伤害，处理死亡及首领生命阈值。
6. 对仍存活且已抵达终点的敌人按出生顺序扣树心、移除；树心归零立即失败，停止后续奖励流程。
7. 清理无效弹道与敌人，更新统计；出怪游标耗尽且无存活敌人时结束本波。

V0.1 的同 tick 边界约定：**伤害结算优先于离场扣血**，终点伤害可在这一个固定步内救场。首领生命阈值带来的速度变化从下一 tick 生效；减速命中从下一 tick 的移动开始生效。此顺序属于技术细化，需用边界测试固定。

### 5.3 索敌、弹道与伤害

- 先筛选有效且在射程内的敌人，再按模式排序；首要键相同后比较剩余路程，再比较出生序号。默认模式直接按剩余路程与出生序号。
- 首版最多几十只敌人，先采用遍历索敌，不预先实现空间树；出现性能证据后再引入空间分桶。
- 攻击开始即视为发射，取当时最终攻击与强化倍率形成弹道快照；命中时读取敌人的当前护甲与减伤。
- 普通弹道以配置速度追踪目标，目标死亡或离场即消失；允许一 tick 跨越目标距离时直接命中，不穿过目标继续飞行。
- 狐狸以命中点为圆心查询敌人，主目标也只结算一次。穿甲参与护甲公式，护雾与首领减伤在护甲后相乘，不再施加第二次最低 1 点限制。
- 攻击冷却与计次能力独立保存，空等不积累计次；每波开始冷却为可攻击，能力次数为 0。
- 减速使用来源 ID、强度和到期 tick；同来源刷新，不同来源各自到期，强减速失效后可回退到尚有效的弱减速。
- 羊的助威按覆盖实时计算，只取最大值，不影响自己或其他羊；换位只在准备阶段发生。

### 5.4 胜败与准备阶段

普通战斗 3 波，精英与首领节点 4 波。最后一波结算时先检查失败，再发放奖励。敌人离场是有效的波次处理结果，因此首领突破但树心仍大于 0 时也能完成节点；最终首领突破要记录“险守净土”。

波间清理减速、弹道与临时敌人状态，重置攻击计时和计次能力；每场第一次漏怪减伤的使用标记只在整场开始重置，不能每波重置。部署位置在同一场波间保留，跨地图时回到后备待部署状态。

## 6. 合成、属性与变异的具体实现

### 6.1 单一属性计算入口

`PetStats.resolve(instance, definitions, relics, auraContext)` 返回最终属性与逐项来源说明，预览、战斗和宠物详情共用它，不在 UI 重算。

顺序遵循玩法设计：物种 → 星级 → 自身变异 → 遗物 → 助威 → 敌方护甲与状态。攻击型星级倍率 1 / 2.2 / 4.8；羊通过星级和词条查助威专用表。攻速限制 0.2～5 次/秒，攻击射程最低 1 格；不能把“每秒次数”误当“攻击间隔”直接相乘。

静谧树脂的资格在遗物生效前判断；助威来源只取最强。变异替换时从基础数据完整重算，不对当前最终值加减，避免反复打开面板或读档造成属性累积。

### 6.2 合成使用两步事务

`PreviewMerge` 是只读查询，不消耗资源、不推进随机流。`ConfirmMerge` 与 `ResolveMutation` 才能改状态：

```text
ConfirmMerge(opId, mainId, secondaryId, useCatalyst)
  校验阶段、两素材存在且不同、同种同星、非三星、资源与当前无待决事务
  根据教学 / 保底 / 遗物 / 催化计算概率
  用变异随机流判定并抽固定候选
  一次提交：移除素材、生成结果、保留主素材位置、释放副位置、
            扣催化、更新保底、创建 PendingMerge、保存随机状态
  保存成功后展示结果；有候选时保持子状态锁定

ResolveMutation(opId, candidateId 或 KEEP_DEFAULT)
  校验选项属于已保存候选
  写入唯一词条、更新实际采用图鉴、结束事务并保存
```

确认后不允许返回上一步恢复素材；中断或读档时回到同一候选面板。`opId` 去重防止双击；保持默认不退催化、不恢复保底。无新变异时直接完成合成，仍使用相同事务机制。

### 6.3 概率细节

- 保底计数为连续未触发次数，达到 4 时本次必定触发；触发归零，未触发加 1。
- 概率用整数基点表示：20% = 2000，催化 +3000，摇铃 +1000，上限 10000，避免小数边界判断混乱。
- 必定触发时禁用催化露；只继承旧变异不算触发。
- 候选从适用池排除默认旧词条后无放回抽样；不足两种就展示实际数量，羊已有变异时只展示一种新词条与保持默认。
- 首次教学固定巨力 / 躁动，不消耗催化露且重置保底；教学进度必须持久化，不能通过重新开始反复获得教学奖励。

## 7. 路线生成、节点和经济的具体实现

### 7.1 路线生成与验证

1. 开局使用地图随机流生成两区节点类型、连线、地图、遭遇和奇遇 ID；第二区域可先隐藏，数据已固定。
2. 每层按玩法模板生成节点，分岔层 2～3 个，首领层一个。只连接相邻层，使用层内横向顺序减少交叉线。
3. 除常规可达性外，验证状态 `(nodeId, hasVisitedCapture)`：入口以 false 开始，走到捕捉地变 true；如果能以 false 到首领，该图不合格。
4. 要让第 2 层绕过捕捉的分支在第 6 层只能连到捕捉，同时仍保留其他分支选择；不能只保证地图中“存在一个捕捉地”。
5. 检查每个可达第 4 层节点至少有一条直连第 5 层营地的边，确保进入该层时能选择休整。
6. 每个节点必须从入口可达并能到达首领，无孤点、死路、重复 ID 和非法类型。
7. 限定次数重试；仍失败则使用预先校验的固定备用图，并记录种子与失败原因。测试覆盖大量种子及备用路径。

进入节点先锁定当前选择并保存。只有节点完成且待领取项已处理后才开启下一层，不因关掉面板自动完成，也不允许重新选择上一节点。

### 7.2 动态奖励与固定遭遇的边界

设计同时要求“开局固定地图与遭遇”和“奖励至少含持有物种”。实施拆分如下：

- 开局固定节点类型、战斗内容和奇遇 ID，不针对当前阵容改敌人。
- 萌宠候选在首次打开该节点的奖励或捕捉界面时，依据当时队伍生成一次，并连同随机流状态保存；之后整理队伍或读档均不刷新。
- 普通奖励和商店持有物种为空时回退到猫。捕捉“仍可合成物种”指持有至少一只非三星的物种；若只有三星，则优先持有物种，仍无持有物种时使用全池候选。
- 首次捕捉至少包含猫；其余捕捉与奖励按设计保底物种，不重复展示同种候选。

这部分是对生成时点与边界的实现补充，不改变奖励数量、概率或敌人强度。

### 7.3 领取、购买与节点结算

统一采用“检查 → 在副本计算所有变化 → 校验不变量 → 持久化提交 → 发布事件”的命令流程。钱不足、队伍已满或保存失败时，不能只完成一半操作。

- 奖励项记录独立 ID 和领取状态，金币、催化和遗物只能处理一次。
- 满员新宠留在本节点待领取区；可以合成、放归或明确放弃。离开节点前必须处理完，不提供跨节点临时仓库。
- 捕捉免费两只按领取游标逐只接收，付费追加仅一次；有孪生项圈时免费组全部接收后追加遗物奖励一次，弃领组内萌宠则不触发“领取完”条件。
- 付费追加与宠物接收同事务完成，容量不足不扣钱；遗物追加也支持待领取与明确放弃。
- 奇遇支付树心后必须至少剩 1；宠物交换先移除付出对象再检查接收容量，全额完成才提交。
- 游商货架固定、库存按物品标记，移除变异服务限一次且无变异时不可购买。
- 营地互斥三选一，选择后立即提交并锁定；树心恢复截断到上限。
- 放归返还按星级 3 / 6 / 12，禁止战斗进行中放归，已部署者放归时同步解除树桩绑定。

### 7.4 遗物与奇遇扩展点

遗物效果使用有限处理时点：获得时、计算属性时、计算合成概率时、捕捉免费组完成时、首次漏怪时、营地恢复时。不扫描 UI 节点推导效果，不让每件遗物独立订阅全局事件造成重复触发。

首次漏怪软垫即使将伤害减至 0 也消耗本场次数；暖灯获得时的 4 点恢复与遗物入包同事务处理。遗物奖励排除已拥有项，不足三件按实际展示，空池换 20 金币。

奇遇配置只引用已实现的效果枚举，例如 `SpendGold`、`HealHeart`、`GrantPet`、`RemoveMutation`；不通过 `eval` 执行 JSON 文本。

## 8. 存档、随机一致性与故障恢复

### 8.1 随机数

采用有明确算法版本的可种子化 32 位 PRNG，保存内部状态；测试固定输入输出。根种子派生相互独立的 `map`、`reward`、`mutation` 随机流；纯表现随机另行处理，不读取玩法随机流。

地图用 map，节点候选用 reward，合成判定与候选用 mutation。预览、动画、改变站位与攻击次数均不推进 mutation。强制教学与必定触发分支的抽样消耗约定也应固定，算法或规则变化提升版本号。

### 8.2 保存内容与触发点

- 保存信封包括 `schemaVersion`、`contentVersion`、递增 `revision`、时间、档案、本局状态、随机流、ID 计数器及完整待处理事务。
- M0 即建立序列化与恢复入口，M2 就保存合成事务，不能等 M6 才发现状态不可序列化。
- 每个玩家状态变更命令、节点切换、波次边界、进入后台和显式暂存退出后保存。
- 运行中每 2 秒在完整 tick 结束后保存一次快照，保存敌人、弹道、冷却、状态到期、首领阶段和遗物标记。
- 显式暂存退出恢复到已保存的精确逻辑状态；异常关闭恢复到最近一次成功快照，最多可能回退约 2 秒，不承诺浏览器强杀时还能执行退出回调。
- 读档不会补算离线战斗；表现动画根据当前状态重建，不需要保存 Tween 本身。

### 8.3 Web 存储与提交

通过 `SaveRepository` 封装 `sys.localStorage`，不在纯逻辑中直接访问浏览器。使用 A/B 两个保存槽：写入较旧槽的新 revision → 回读解析与校验 → 更新当前槽提示。加载时检查两个槽，选择版本兼容且校验通过的最高 revision；提示键丢失也可恢复。

单个快照包含本次相关的 Profile 与 Run 变化，避免跨键写到一半造成“图鉴记录了，但宠物还没生成”等问题。会话更新串行执行，持久化失败则保留旧状态并显示可重试提示，禁止静默宣称保存成功。校验摘要用于损坏检测，不宣称具备防作弊能力。

若运行中写入失败，暂停模拟并提示存储不可用；玩家可以释放空间后重试或明确选择退出。测试存储配额不足、非法 JSON、一槽损坏、两个槽都损坏、不支持版本。不得自动清除全部 localStorage；只操作本游戏前缀的键。

## 9. Cocos 展示、输入与资源实施

### 9.1 输入和布局

- 鼠标与触摸共用命令入口，点击选择 + 点击目标作为拖放的替代方式。
- 使用触点 ID 锁定一次拖动，处理 `TOUCH_CANCEL`、失焦、面板关闭和后备栏滚动手势。
- 屏幕触点先进入统一 UI 坐标，再通过目标 `UITransform` 转换为局部坐标；不得把屏幕坐标直接作为树桩本地坐标。相关 API 见 [UITransform](https://docs.cocos.com/creator/3.8/api/en/class/UITransform)。
- 每次投放由领域层检查阶段、占用、部署上限与宠物是否存在，失败只回滚拖动预览，不修改真实队伍。
- `Widget` 管外围锚点，`Layout` 管卡片排列；同一节点的同一位置不同时交给 Layout 和手动 Tween 控制。变异卡片展示优点、代价及完整属性，不依赖颜色传达状态。
- 仅验证竖屏玩法，覆盖 360×640、390×844 等手机比例；横屏和正方形窗口必须显示提示并停止模拟，恢复方向时不得补算离开期间的战斗时间。

### 9.2 资源与表现

- 静态基础预制体、图片和音频通过 `@property` 引用；配置与确需按名称选择的资源进入 `resources/`，首版不提前划分多个 AssetBundle。
- 主入口场景、预制体与 `.meta` 由匹配版本编辑器或其正式扩展生成；不拼接未经验证的序列化 JSON。
- 为常用敌人、宠物与弹道表现建立池，归还时清监听、Tween、动画状态、颜色、标签、血条、绑定 ID 与异步请求标记。
- 逻辑对象死亡后先断开绑定再回收节点；旧弹道引用逻辑 ID，不引用可能被复用为另一个敌人的池节点。
- 加载回调检查错误、组件有效性和本次请求序号，避免返回地图后迟到的回调生成战斗对象。
- 变异使用物种底图 + 局部缩放/配件/特效，明确区分视觉体型与逻辑射程、命中范围；装饰不能影响规则。
- 战斗渲染仅刷新变化字段；伤害文本和粒子限制数量，音效限制同时播放数。使用图集与统一材质减少状态切换，性能以实测为准。

生命周期和监听使用方式以 [Cocos 生命周期文档](https://docs.cocos.com/creator/3.8/manual/en/scripting/life-cycle-callbacks.html) 为基础；资源身份和移动规范见 [Meta 文档](https://docs.cocos.com/creator/3.8/manual/en/asset/meta.html)。

## 10. 分阶段任务与验收

### M0：工程骨架与数据契约（2～3 人日）

- [ ] **M0-01 启动工程。** 用 3.8.8 打开并导入，建立入口场景与 Canvas；记录预览方式，确认资源与控制台无错误。
- [ ] **M0-02 类型与配置。** 建立领域类型、规则配置和运行时校验器；先填初始资源与猫兔狐的最小数据。
- [ ] **M0-03 会话与时钟。** 建立命令分发、流程状态、固定步驱动和事件接口；UI 不直接改状态。
- [ ] **M0-04 随机与保存外壳。** 建立分流 PRNG、ID 计数器、A/B 存储适配、保存版本及错误返回。
- [ ] **M0-05 可执行检查。** 增加锁定版本的 TypeScript 与 Vitest 开发依赖、锁文件和 `typecheck`、`test`、`validate:config` 命令；测试目标只导入 domain，工具位于根目录。

验收：编辑器与 Web 预览能进入占位入口；配置缺少引用时明确失败；PRNG 与存档往返测试通过。根 tsconfig 保留引擎继承，不手改 `temp/` 声明。

### M1：塔防战斗切片（4～6 人日）

- [ ] **M1-01 路径与出怪。** 实现折线路径、固定出怪表、三波切换和树心扣除；完成雾团、疾跑芽、孢子虫。
- [ ] **M1-02 攻击与状态。** 实现猫的计次攻击、兔的减速、狐的范围伤害、索敌模式和追踪弹道。
- [ ] **M1-03 布阵与表现。** 一个长弯道地图，8 个树桩、最多 6 宠，支持部署、撤下、换位、射程显示。
- [ ] **M1-04 时间与结算。** 准备 / 运行 / 波间 / 胜败状态、暂停、1/2 倍速、运行中快照。

验收：在明确标为测试的沙盒中，能从部署开始完成三波；暂停后敌人、弹道、冷却均冻结；同 tick 树心归零不发胜利奖励；1 倍与 2 倍推进相同模拟 tick 得到相同逻辑结果。沙盒可使用猫兔狐，不冒充正式初始队伍。

### M2：合成与变异核心（4～5 人日）

- [ ] **M2-01 升星与容量。** 实现同种同星校验、三星上限、主副交换、结果站位继承、队伍 12 只限制。
- [ ] **M2-02 属性解析。** 共用预览与战斗属性函数，先接入巨力、躁动、贴贴，再补长臂及专属词条数据。

- [ ] **M2-05 变异反馈。** 制作合成预览与选择面板，显示所有概率来源、优势、代价与最终属性；动画可跳过。

验收：二星普通猫攻击 22，巨力猫攻击 44、攻速 0.65；连续 4 次未触发后下一次必触发；读档不重抽、不重复扣催化；合并两个已部署对象后只占主素材树桩。进行一次定性试玩，记录变异是否让玩家改变位置或分工。

## 11. 测试与质量门槛

### 11.1 优先自动验证的规则

| 主题 | 关键用例 |
| --- | --- |
| 属性 | 星级倍率、替换重算、羊的专用表、遗物资格判定、攻速与射程边界 |
| 合成 | 同 ID 双素材、不同种/星、三星、主副继承、站位、保底重置、催化禁用、只剩一个候选 |
| 事务 | 双击去重、资源不足、满员、保存失败、部分领奖恢复、放弃后关闭节点 |
| 战斗 | 跨多段移动、双入口剩余距离、攻击计数、目标失效、AOE 不重复、减速回退、零树心失败优先 |
| 时间 | 暂停零推进、倍速相同 tick 同结果、首领周期、跨波遗物标记 |
| 路线 | 大量种子可达、每条完整路有捕捉、营地可选、层数正确、备用图通过同一校验 |
| 随机与存档 | 预览不抽样、不同随机流隔离、候选持久化、战斗快照往返、版本不兼容与损坏回退 |
| 经济内容 | 遗物排重/空池、捕捉逐只领取、奇遇剩 1 树心边界、商店限次、首领奖励一次 |

Vitest 只测纯规则与模拟，不用脆弱的 Cocos 假实现模拟整个引擎。快照回归比较规范化逻辑状态，排除时间戳与纯表现字段；恢复快照后继续推进，与未中断模拟进行对照。

### 11.2 必须实机或编辑器验证的内容

- 入口场景、预制体挂载、Inspector 引用、资源导入与缺失脚本。
- 鼠标和触摸拖放的坐标、画布缩放、安全区、弹窗遮挡及按钮命中。
- 暂停、倍速、后台切换、声音与表现是否匹配逻辑。
- 池复用、资源加载失败、离开战斗后的迟到回调、连续多局后的监听和内存。
- Web 构建运行、刷新恢复、localStorage 错误与 HTTP 资源路径。

类型检查通过不等于编辑器可运行；预览通过不等于构建通过。无法运行某项检查时明确记录原因，不用“应该正常”代替验证。

### 11.3 性能观察基线

先在注明设备和浏览器的环境下测量：50 个敌人、6 只宠物、约 100 个表现弹道作为压力起点，观察 1 倍与 2 倍速；目标为桌面预览接近 60 FPS，并记录实际帧耗时、DrawCall、节点数和内存。该压力规模是测试场景，不限制正式波次规则。

连续进入/退出战斗 20 次后，战斗节点、监听数量与持有资源不应持续增长。性能未达标时先定位分配、文本刷新、透明特效与索敌，再决定优化，不凭空设定“已优化”结论。

## 12. 实施补充、风险与变更纪律

以下规则在玩法原文未完全指定，先采用本文约定：发射时锁定伤害参数、命中时读取敌方防御；同 tick 伤害优先于离场；新地图清除部署；奖励首次打开时生成并保存；异常中断恢复最近快照；捕捉无非三星持有物种时的回退规则。

这些约定必须在相应任务实现与测试中明确体现。若试玩需要改变玩家可感知规则，先同步更新玩法文档，再调整计划、配置与测试；不要让隐藏代码分支成为第二份设计。

| 风险 | 预防与处理 |
| --- | --- |
| 手写场景导致静默断链 | 使用编辑器或正式扩展生成结构；检查 UUID 和 Inspector 引用 |
| 逻辑依赖动画，倍速或恢复失真 | 固定步模拟持有全部玩法状态，表现只订阅结果 |
| 存档等到末期才设计 | M0 定义序列化，M2 检查合成中断，M6 执行完整恢复矩阵 |
| 满员奖励、重复按钮造成复制资源 | 所有收支串行事务、操作 ID 去重、待领取游标持久化 |
| 实现顺序掩盖玩法问题 | M2 即试玩变异，M3 即试玩选路，内容扩充依赖观察结果 |
| 需求膨胀 | V0.1 不添加跨种杂交、多词条、局外数值成长、联机或渠道系统 |
